Critical Issues Must fix before launch

C1 — twitter:image tag missing on every page

The Seo.tsx component sets twitter:card, twitter:title, and twitter:description, but never sets meta name="twitter:image". When a LEAF page is shared on X/Twitter, the card will render with no image — a major engagement drop for a social-media-active brand.

Confirmed across all 30 pages (EN + ES). The ogImage variable is already available in Seo.tsx but is not forwarded to a Twitter meta tag.

Fix (src/components/Seo.tsx): Add after the existing twitter tags: <meta name="twitter:image" content={ogImage} />

C2 — og:image is a placeholder on all 14 content pages

Every page uses the same /og-default.jpg (1200×630, 41 KB — correct dimensions). But a single generic image used for all pages will:

  • Produce low CTR on social shares for interior pages (the image has no page-specific context)
  • Prevent Google Discover from associating relevant images with specific pages
  • Make the Webinar pages especially weak — event cards without a visual are ignored

The Seo.tsx source already includes a comment: // TODO: real default OG image, and branded page-hero/ images exist in dist/page-hero/ (24 .webp files including event-calm.webp, hero-support.webp, etc.).

Fix: Pass a page-specific image prop to <Seo> in each major page component using the existing page-hero/ assets. Minimum: Home, Our Program, Webinar 1, Webinar 2, Events, About.

Titles under ~40 characters leave significant keyword real estate on the table. Google displays 50–60 characters; anything shorter misses mid-tail keywords and reduces click-through intent signals.

W3 — Sitemap missing lastmod, priority, and changefreq

The dist/sitemap.xml (30 URLs, correct hreflang structure) omits all optional but beneficial sitemap fields:

  • <lastmod> — tells Googlebot when content was last updated; important for blog and events pages
  • <priority> — signals relative importance (Home = 1.0, key pages = 0.8, blog/privacy = 0.5)
  • <changefreq> — hint for crawl frequency (home/events = weekly, static = monthly)

File: scripts/generate-sitemap.mjs

Fix: Update generate-sitemap.mjs to include per-path lastmod (build date), priority tier, and changefreq in the urlEntry function.

Confirmed in dist/index.html: the three hero carousel images use alt="Slide 1", alt="Slide 2", alt="Slide 3". These provide zero context to screen readers or image search crawlers. The supporting content image uses alt="Wraparound Care" — also weak.

Opportunities Improve ranking potential

O1 — Webinar Event schema missing "performer" and "image" fields

Both webinar pages have solid Event schema with startDate, endDate, location (VirtualLocation), isAccessibleForFree, and description. Two fields would significantly improve Google Events eligibility:

  • "performer": Bryan Post and/or Jeanette Yoffe (Person nodes) — Google requires a speaker for rich results on webinar events
  • "image": an absolute URL to a 1:1, 4:3, or 16:9 image — required for Google Events rich cards

O2 — Donate page missing DonateAction or GiveAction schema

The /donate page has only the base Organization schema. Adding a DonateAction node referencing the organization as recipient would help search engines surface the page in nonprofit/donation queries and supports Google's Knowledge Graph for LEAF as a nonprofit.

O3 — No BreadcrumbList schema on interior pages

Interior pages (Our Program, About Us, FAQ, etc.) have no BreadcrumbList schema. Breadcrumbs appear in Google SERPs and increase click-through rates by showing users where they are in the site hierarchy. With a flat site structure (most pages are one level deep), this is quick to implement.

Quick implementation: Add a BreadcrumbList node to the jsonLd prop in each page component with two items: Home → [Page Name].

O4 — NGO schema type: add "LocalBusiness" or "GovernmentService" as additional @type for local pack eligibility

Current Home schema uses ["NGO","Organization"]. While NGO is valid schema.org, Google's local pack primarily recognizes LocalBusiness subtypes. Adding "SocialService" (a LocalBusiness subtype, valid for adoption/wraparound organizations) alongside NGO would improve local search visibility for queries like "adoption support Sacramento" or "wraparound services California".

O5 — Sitemap includes /privacy-policy and /donate (low-value pages waste crawl budget)

The generate-sitemap.mjs PATHS array includes /privacy-policy and /donate. Privacy policy pages are never ranked for organic traffic; including them dilutes crawl budget priority signaling. These pages should be either removed from the sitemap or given priority 0.1.

Fix (scripts/generate-sitemap.mjs): Remove "/privacy-policy" from PATHS (it's indexed via internal links). Keep "/donate" but lower its priority.

O6 — No sitelinks search box schema or WebSite SearchAction

The existing WebSite schema node does not include a SearchAction property. Adding this (pointing to a search URL pattern) enables Google to display a sitelinks search box in branded SERPs when users search for "LEAF Wraparound" directly.

O7 — llms.txt is present but lacks structured sections for AI crawlers

dist/llms.txt exists (a positive signal for AI citation). Review its structure to ensure it follows the emerging llms.txt specification with # Title, > tagline, and labeled ## Section headers, plus explicit links to key pages. This is forward-looking but increasingly important for AI-driven zero-click results.
